# 2026.251.1403 — fix(appium): scope the baked av-suite session lifecycle to its own session_file: baked (E-5 R3)

## Summary

The E-5 check-android-emulator-pod bed fails its evidence gate because TWO session lifecycles share ONE session file. The distro fixture owns the ONE-identity WebDriver session (its overlay `session-create` with the 3600s caps) that the runner's instrument recorder brackets; this layer's baked av-suite has its OWN `appium-session-create`/delete + transient session (120s caps) that ROTATES the SAME shared file and DELETES the previous session server-side (`delete-previous`) — killing the fixture's pinned session under the open recorder bracket (runs 2026.251.1102/1122: the recorder's final `stop_recording_screen` 404'd, row.json `segments=0`, evidence gate fail).

**Fix (E-5 R3 session-scoping):** every `appium:` step in this layer's baked plan (the `appium-session-create`, the av-suite, `appium-screenshot`, `appium-session-delete`) now authors `session_file: baked` — the plugin-appium companion PR (#7) adds the optional `session_file` input whose default is the SHARED box file and an explicit key resolves an ISOLATED file (`<box>_baked.json`). The baked av-suite therefore keys its OWN session lifecycle and NEVER touches the fixture+recorder's shared file; the two lifecycles cannot churn each other. Default (unset) steps everywhere else keep the shared file, unchanged.
